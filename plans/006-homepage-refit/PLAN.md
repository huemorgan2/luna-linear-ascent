# 006 — homepage refit: the movie plays itself, the cast gets its faces

## Problem

Owner request (2026-08-08, verbatim intent):

1. **The intro movie scrolls; it should play.** "THE STORY SO FAR" I–IX is
   nine cards down the page. Wanted: one card that plays **in place, over
   time, like it is in the game** — an image gallery that advances only
   when the panel's animation has finished playing AND the text has
   finished writing. **No skip button.** Dot-like ANSI shapes that move.
   The text writes itself **at reading speed** (the current typewriter is
   ~250 chars/s — far faster than anyone reads).
2. **The class portraits are wrong.** WARRIOR should be **the woman**;
   ARCHER should use the **more armoured elf** we already have; SORCERER
   is **the giant dwarf wizard** — his image must become a **massive
   giant, two heads taller than the others and wider, holding a staff** —
   and the image must change **in the game as well** (the game's `wick`
   portrait is the same stout dwarf; today he holds a tankard, not a
   staff).
3. **The floors strip scrolls horizontally.** Wanted: **vertical, no
   scroll strip, exactly the first 6 floors**, each titled **"Floor 1"**
   … "Floor 6" — not "F1".
4. **THE STONE OF ERAS copy** must say **we remember, no matter what
   happens on the hundredth floor**.
5. Deploy.

## Root cause

Not a bug — the page shipped in 003/004 as a static scrolling brochure;
the request upgrades it toward the in-game presentation. No emergency
mitigation needed.

## Current facts (verified 2026-08-08)

- Homepage: `worldd/static/site/index.html` — 9 story cards in `#lore`,
  `.trio` portraits (plate / elf_leather / wick), `.strip` of 10 floor
  figures captioned `F1 · …`, Stone copy without the "we remember" line.
- Typewriter: `site.js typeCard()` — 2 chars / 8 ms.
- Intro GIFs (`worldd/static/intro-movie/`): singles run 6240 ms
  (78 f); split pairs `theft/refugee/stone/shard` have `_intro` 4800 ms
  (plays once) + `_loop` 1920 ms. The in-game card plays `_intro` once
  then swaps to `_loop` (`render.py _fx_split`) — the player mimics this.
- Game portraits are 100×200 1-bit PNGs generated by
  `plugin-linear-ascent/tools/generate_030_art.py` (Gemini paint →
  center-crop → Bayer 8×8 → white ink on alpha). No woman portrait and
  no dwarf-wizard-with-staff exists anywhere in the art inventory —
  the two new images must be generated in the same pipeline.
- The game's only class-adjacent face is NPC **Wick**
  (`portrait_wick_100x200.png`, lodge keeper, tankard) — that is "the
  game image" to change.
- Parallel Cursor session holds dirty plugin/luna working trees — stash
  dance around vendor runs, exclude its files from every commit.

## Fix — phases

- **Phase 1 — the faces** (`phase-1/PLAN.md`): generate the woman
  warrior and the giant dwarf wizard (staff) in the 030 pipeline; giant
  rendered on a 140×260 canvas (others 100×200 → ~2 heads taller,
  wider); replace `portrait_wick_100x200.png` in the plugin (game) with
  the wizard; copy the armoured-elf portrait to the site; wire the trio.
- **Phase 2 — the movie** (`phase-2/PLAN.md`): in-place story player in
  `index.html`/`site.js`/`site.css` — auto-advance when GIF cycle AND
  typing complete, reading-speed typewriter, moving ANSI dot marks, no
  skip control, loops I→IX→I; scripts-off and reduced-motion keep the
  readable card list.
- **Phase 3 — floors & Stone** (`phase-3/PLAN.md`): first 6 floors,
  vertical, "Floor N · NAME" captions; Stone copy says we remember no
  matter what happens on the hundredth floor.
- **Phase 4 — ship** (`phase-4/PLAN.md`): plugin 0.51.0 bump + tests,
  vendor, worldd tests (test_site additions), secret scan, commit,
  deploy `srv-d9ha3csvikkc73ff5rg0`, `/health` game 0.51.0, dojo
  walkthrough (`dojo/01-homepage-refit.md`) vs production, archive
  results.
